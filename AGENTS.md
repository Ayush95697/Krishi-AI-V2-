# KrishiAI+ Development Rules

1. Never fabricate technical facts.
2. Verify current technologies when a decision depends on current tooling.
3. Prefer official documentation for framework/cloud decisions.
4. Keep frontend, backend, ML, RAG, and infrastructure boundaries clear.
5. Do not mix database logic into API route files.
6. Do not put business logic into React components.
7. Do not hard-code secrets.
8. Do not fabricate ML metrics.
9. Do not fabricate agricultural recommendations.
10. Do not claim weather forecasts represent exact farm microclimate.
11. Do not claim GPS determines exact soil health.
12. Every new dependency must have a reason.
13. Before major architectural changes, explain the trade-offs.
14. Run tests/lint/build checks after meaningful implementation work.
15. Make incremental changes rather than rewriting unrelated code.
16. Do not implement future features just because empty directories exist.
17. Preserve separation between planned functionality and implemented functionality.
